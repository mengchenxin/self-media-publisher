# 浏览器发布操作手册

用 `agent-browser` 完成发布的实操手册。**先读「零、红线」，再读「一、会话与登录」，最后按平台查「三、各平台操作序列」。**

---

## 零、红线（不可跳过）

1. **发布是外部且不可撤销的动作。** 群发出去的公众号消息、发出去的微博，删不掉痕迹。因此：
   - **必须先存草稿 / 先填完表单并截图，把截图给用户看，得到明确「发」的指令后才点最终发布按钮。**
   - 用户没确认就只做到「草稿或截图」为止，然后在回复里说明卡在哪一步。
2. **不得伪造结果。** 没真正发出去就不能在台账里写 `published`。失败写 `failed:<原因>`，跳过写 `skipped:<原因>`。
3. **不发未过合规预检的内容。** 先跑 `scripts/compliance_check.py`，有 `block` 级命中必须回改。
4. **不替用户登录。** 遇到登录页、验证码、扫码，一律暂停并请用户手动完成后告知。

## 一、会话与登录（2026-10-11 实测）

### 1. 最重要的一条：默认不持久

`agent-browser` 默认把浏览器 profile 建在临时目录，名字带随机 UUID：

```
C:\Users\<你>\AppData\Local\Temp\agent-browser-chrome-<随机UUID>
```

进程退出即废弃。**也就是说，不带参数运行时登录态不跨 `close` 保留 —— 每轮任务都要重新登录所有平台。**

实测依据：`--user-data-dir` 参数指向上述临时路径（Win32_Process 查得）。

这不可接受，所以**本项目必须每次显式指定 profile**。

### 2. 固定启动命令

```
agent-browser --args "--no-proxy-server" \
              --profile "C:/Users/<你>/.agent-browser/profiles/self-media" \
              open <第一个平台的发布页>
```

- `--profile <目录>`：在该目录建立**持久** Chrome profile。实测重启后目录结构完整保留（`Default/`、`Local State`、`Preferences`、`Login Data`），登录态可跨轮复用。
- **首次使用该 profile 时，需要人工登录一次各平台**，之后长期有效，直到平台侧主动让会话失效。
- `--profile Default`：改用本机 Chrome 的默认 profile，可直接继承你日常 Chrome 里已有的登录态。适合平台已在你常用 Chrome 登录过的情况。代价是会占用你的 Chrome 用户目录 —— **若 Chrome 正在运行会冲突，必须先完全退出 Chrome**。

### 3. 启动参数只在启动那次生效（易踩坑）

`--profile`、`--args` 属于**守护进程启动参数**。守护进程已在运行时再传，会被静默忽略并告警：

```
⚠ --profile ignored: daemon already running. Use 'agent-browser close' first to restart with new options.
```

所以**要换 profile 或改启动参数，必须先 `agent-browser close --all`**。别以为传了参数就生效了。

### 4. 代理问题

若环境变量里有代理设置：

```
HTTP_PROXY=http://127.0.0.1:<端口>/
HTTPS_PROXY=http://127.0.0.1:<端口>/
```

Chromium 会读取这两个变量作为代理设置，代理不可用时报：

```
✗ Navigation failed: net::ERR_NO_SUPPORTED_PROXIES
```

页面根本打不开，后续一切操作都会失败。处理方式二选一：

- 加 `--args "--no-proxy-server"` 直连（上面的启动命令已带）；
- 或确认该代理端口确实在监听，则去掉这个参数。

**判断依据**：`open` 之后用 `agent-browser get url` 检查。若返回 `chrome-error://chromewebdata/`，就是网络/代理问题 —— **不要继续往发布页填表**，先解决连通性。

### 5. 任务内不要 close

- 同一会话内 cookie / localStorage / 登录态跨命令保留。
- **整轮任务（含所有平台发布 + 数据回收）只在最后 `close` 一次。** 中途 `close` 会结束守护进程，下一个平台要重连、重开参数。
- 结尾（含失败路径）必须 `close`，避免留下僵尸守护进程和 Chromium 进程。

### 6. 登录态探测（每个平台发布前必做）

```
agent-browser open <平台发布页>
agent-browser wait 1200
agent-browser snapshot
```

从快照判断：

- 出现账号昵称 / 头像 /「发布」按钮 → 已登录，继续。
- 出现「扫码登录」「登录/注册」「请输入手机号」→ **停止**，把浏览器窗口交给用户手动登录，然后重新 `snapshot` 确认。

**不要用 `eval "document.cookie"` 判断登录态** —— 实测报 `Access is denied for this document`，读不到。以 `snapshot` 里是否出现账号信息为准。

### 7. 其他可用的登录态机制（按需）

| 机制 | 用途 |
| --- | --- |
| `--session-name <名字>` | 按名字自动保存/恢复 cookies + localStorage，比整个 profile 更轻 |
| `--state <json>` / `agent-browser state save <json>` | 把登录态导出成 JSON，便于备份或迁移 |
| `--auto-connect` | 连接到一个**正在运行的** Chrome，直接复用其登录态（不新开 profile） |
| `agent-browser auth save/login` | 保存账号密码并自动登录，适合无扫码验证的平台 |

首次为某平台登录成功后，顺手备份一份：

```
agent-browser state save <输出目录>/auth-<平台>.json
```

万一 profile 损坏，可用 `--state` 快速恢复，不必重新扫码。

若 `open` 报守护进程 / Chromium 启动失败，**不要重试同一命令**，按 `agent-browser` skill 的 `references/troubleshooting.md` 排查。

## 二、通用发布循环

对每个平台按此 6 步走，任一步失败进入降级。

1. **导航**：`open <发布页>` → `wait --load load` → `snapshot -i`。
   - 拿到交互元素 ID 后**尽量用快照给出的选择器**，不要凭记忆猜 CSS。
2. **填标题**：定位标题输入框 → `type`（若已有默认内容先 `click` 后全选清空）。
3. **填正文**：
   - **纯文本平台**（知乎富文本、小红书、微博、头条、公众号）→ `type` 输入纯文本。
   - 需要行内格式/图片时，改用平台工具栏按钮或「粘贴」通道；**不要指望 Markdown 标记自动渲染**。
   - 正文长度超过约 2000 字时，`type` 可能很慢，可先填入再 `snapshot` 校验前 200 字是否完整。
4. **上传图片**：用平台的上传控件（通常 `<input type="file">` 被隐藏，需先 `click` 触发）→ 等待上传完成（`wait` + `snapshot` 确认出现缩略图）。**首图务必确认顺序正确**。
5. **加话题/标签/分类**：小红书和微博的话题**必须从联想下拉里点选**，纯文本井号可能不生效；知乎/头条的话题标签填满到上限。
6. **校验 + 交人工确认**：`screenshot` 一次整页 → 检查标题未截断、图片已就位、话题是蓝色链接状 → **把截图给用户，等确认**。
   - 确认后：点「发布」或「群发」→ 再 `wait` + `snapshot`/`screenshot` 验证成功页（出现「已发布」「发送成功」或跳转到内容页）。
   - 未获确认：停在草稿（多数平台有「保存草稿」），记录 `draft`。

## 三、各平台操作序列

> 路径与字段以 `references/platform-specs.md` 为准；下面是操作层面的注意点。

### 微信公众号

- 登录态：`mp.weixin.qq.com` 首页出现账号昵称即为已登录；扫码有效期约 5 天，中途可能掉线。
- 进入「新的创作」→「图文消息」，编辑器在新标签/新页面。
- 标题、作者、摘要分三处填写，**摘要需手动展开填写**，否则自动截取。
- 封面在页面下方独立区域上传，**大图与小图要分别设置**。
- 正文粘贴：公众号编辑器对复制内容做样式清洗，**格式会丢**。若正文带样式，改用「导入 Word/从链接导入」或直接 `type` 纯文本。
- 群发按钮有二次确认弹窗，需再点一次；**这一步之前必须已完成用户确认**。
- 成功后出现「已发送」或跳回素材列表。

### 知乎

- 登录态：右上角出现头像即为已登录。
- `zhuanlan.zhihu.com/write` 直接进编辑器；填标题 → 正文 → 右侧添加话题（最多 3）。
- 编辑器富文本：直接 `type` 的 `#`、`-`、`1.` **不会自动转格式**。需要小标题时，点工具栏标题按钮，或先在本地生成 HTML 再走粘贴通道。
- 「发布」按钮在右上，点击后有设置弹窗（话题、原创声明），确认后提交。
- 成功：跳转到文章页，URL 形如 `zhuanlan.zhihu.com/p/<id>`，**把它记进台账**。

### 今日头条

- 登录态：`mp.toutiao.com` 出现「发布」按钮即为已登录（有短信验证的二次校验，可能要求本次登录）。
- 发布页有「文章 / 微头条 / 视频」切换，确认停在「文章」。
- 标题输入框会**实时显示剩余字数**，把剩余字数为 0 或负数作为截断预警，回改标题。
- 正文内嵌图片需逐张走「图片」按钮上传，不支持粘贴外链图片。
- 「预览并发布」→ 预览页确认 → 「发布」。
- 新号可能提示需实名，若被拦则记录 `skipped:need_verification`。

### 小红书

- 登录态：`creator.xiaohongshu.com` 出现账号名即为已登录。**掉线频繁**，务必每次探测。
- 发布页有「上传图文 / 上传视频」tab，选「上传图文」。
- 图片是第一步：先上传图片，**再**才出现标题和正文输入区。顺序错了会找不到输入框。
- 标题 ≤ 20 字，输入框有计数。
- 正文里的话题：`type` `#` 后会弹联想框，**需从联想项点选**并回车确认，才算真话题。
- 底部「发布」按钮；有「定时发布」选项。
- 成功：跳转到「笔记管理」并出现该笔记。**限流提示不会当场显示**，台账里把小红书标记为「需事后回查」。

### 微博

- 登录态：`weibo.com` 右上角出现头像。
- 首页发布框是 SPA：`type` 之后**内容可能没绑定到组件状态**。稳妥做法：`type` 前先 `click` 输入框，输入后再 `blur` 或直接点「发送」触发读取。
- 话题：输入 `#` 弹联想 → 选词 → 自动补全为 `#话题#`。
- 图片：点图片按钮 → 上传 → 等待缩略图出现（微博上传较慢）。
- 「发送」后右上出现 Toast「发送成功」即为完成。
- 长文（>2000 字）必须走 `weibo.com/ttarticle/p/write`，否则被截断。**超过 2000 字时自动切到长文入口。**

## 四、失败降级矩阵

| 失败点 | 处理 |
| --- | --- |
| 登录态失效 / 验证码 | 暂停，请用户手动登录后继续；台账记 `blocked:login` |
| 页面改版导致选择器失效 | `snapshot -i` 重新取元素，以页面为准；任务结束回改 `platform-specs.md` |
| 字段超限被截断 | 回改该平台版本后重试，最多重试 2 次 |
| 图片上传失败 | 缩减图片体积/数量后重试；仍失败则去掉图片发布（正文注明），台账记 `published_no_image` |
| 审核/权限拦截 | 停止，保留草稿，台账记 `blocked:<原因>`，把原文路径交给用户手动处理 |
| 最终发布按钮点击无响应 | 不强发。停在草稿 + 截图，交用户手动 |

**原则：宁可停在草稿，不可发出错误内容；宁可标记失败，不可谎报成功。**

## 五、结局收尾

整轮任务结束（无论成败）：

```
agent-browser close
```

注意：如果用户接着要**立刻做数据回收**（例如补抓上一篇文章的 24h 数据），不要 `close` 再重开 —— 保持守护进程存活，直接 `open` 下一个地址。只有整轮任务（含数据回收）全部做完才 `close`。

然后调 `scripts/publish_log.py` 把本轮每个平台的状态写入台账，最后向用户汇报表格：平台 / 状态 / 链接 / 备注。

## 六、数据回收（发布后 24h / 72h）

发布成功只是过程。**24 小时和 72 小时各回抓一次**，因为：

- 24h 反映平台首轮推荐的结果；
- 72h 是推荐基本停止的时点，与 24h 对比才能判断这篇内容是真有生命力，还是只吃了一波初始流量。

### 操作

对每个状态为 `published` 的平台：

```
agent-browser open <该平台数据后台地址>   # 地址见 platform-specs.md 第五节
agent-browser wait --load load
agent-browser snapshot
```

从快照文本里提取指标，写回数据台账：

```
python scripts/stats_log.py add --log <输出目录>/stats-log.csv \
    --article "<标题>" --platform 公众号 --age 24h \
    --reads 860 --likes 34 --comments 12 --shares 8
```

全部抓完后出对比报告：

```
python scripts/stats_log.py report --log <输出目录>/stats-log.csv --article "<标题>"
```

### 抓不到怎么办（重要）

**部分平台的数据面板是 canvas 图表，`snapshot` 拿不到数值文本。** 这时不要编数字：

- 改 `agent-browser screenshot` 截图，把图交给用户，请用户读数；
- 或直接请用户自己在后台看，把数字告诉你。

**抓不到的指标留空，不要填 0。** 「0」和「未知」在复盘时是完全不同的信息。

### 时点纪律

- **不要发布后立刻抓** —— 数据还在跳，此时的数字没有复盘价值。
- 两次抓取尽量落在同一时段（例如都是上午 10 点），否则日周期波动会污染对比。
- 小红书在发布后 48h 内还要额外确认是否被限流（`platform-specs.md` 有说明），限流的数据特征通常是曝光量显著低于同账号历史水平。

### 回收后要做什么

`stats_log.py report` 会算出 24h → 72h 的阅读增幅。据此判断下一步：

| 观察 | 含义 | 动作 |
| --- | --- | --- |
| 72h 相比 24h 大幅增长 | 内容被持续推荐 | 同题材可再做一篇 |
| 72h 几乎没涨 | 推荐已停，内容没跑出来 | 考虑换标题重发 |
| 某平台显著低于其他平台 | 该平台的改写没适配好 | 回看该平台版本的开头与话题 |
| 小红书曝光异常低 | 可能被限流 | 检查正文是否存在导流话术 |

## 七、配图：文字卡片用 HTML 渲染，不要用 AI 生图

**为什么**：ImageGen 渲染中文长文本不可靠 —— 会糊字、缺笔画、写错字。而小红书首图恰恰需要精确的大字排版。HTML 渲染 + 浏览器截图完全可控、可复现，改一个词重跑一次即可，也不消耗生图额度。

### 生成

```
python scripts/render_card.py --title "居家办公3年|我以为很爽|结果效率崩了" \
                              --kicker "远程办公 / 效率" --footer "@你的账号" \
                              --theme ink --out <输出目录>/images/xhs-1.html
```

- 标题里的 `|` 表示**强制换行**。首图断行位置对可读性影响极大，值得手工控制。
- `--list-themes` 查看全部主题（`ink` 黑底黄最醒目，`paper` 米白底橘最耐看）。
- 字号默认按字数与行数自动计算，可用 `--size` 覆盖。

### 截图（顺序不能错）

```
agent-browser close --all
agent-browser --args "--no-proxy-server" --profile <profile> \
              open "file:///<卡片 html 绝对路径>"
agent-browser set viewport 1080 1440
agent-browser open "file:///<卡片 html 绝对路径>"     # ← 必须再打开一次
agent-browser wait 700
agent-browser screenshot <输出目录>/images/xhs-1.png
agent-browser set viewport 1440 900                  # 截完还原
```

**为什么 `set viewport` 之后必须再 `open` 一次 —— 实测结论，别省这一步：**

| 试过的做法 | 结果 |
| --- | --- |
| **先 open → set viewport → 再 open** | ✅ 视口 1080×1440，卡片完整 |
| 先 set viewport → 再 open | ❌ 视口仍是默认 1258×566 |
| 只加启动参数 `--window-size=1080,1440` | ❌ 视口不变 |
| open → set viewport → 直接 screenshot | ❌ 得到纯空白图 |

原因是 `set viewport` 会把当前页面**重置为 `about:blank`**。不重新打开，截到的就是那张空白页。

### 截完必须肉眼检查

用 Read 工具打开 PNG 看一眼，重点两处：

1. **底部署名有没有被挤出可视区。** 视口一旦出现滚动条，滚动条会挤压尺寸把页脚顶到可视区外。
   模板里已加 `overflow: hidden` 防这个问题；看不到页脚时先查这里。
2. **标题有没有溢出、断行是否难看。** 3 行以上要适当减小 `--size`。

### 其他平台配图

- **公众号封面 2.35:1**：同一套方法做横版卡片，把模板里 `.card` 的宽高改成 900×383 即可。
- **非文字类配图**（场景图、示意图、实物图）才用 ImageGen。
- 生成/截图完成后，务必跑 `preflight_check.py` 校验像素比例 —— 比例不对发布页会裁切。
