# 平台规格表

本文件是「一稿多改」与「浏览器发布」的字段依据。所有字数、比例、入口路径以本表为准。

> **时效性提醒**：平台会改版。任何一次发布前，若报错或字段对不上，先 `agent-browser snapshot -i` 抓一次发布页的真实 DOM，以页面为准，并在任务结束后回来修正本表。

---

## 一、长文平台

### 1. 微信公众号

| 项 | 规格 |
| --- | --- |
| 后台入口 | `https://mp.weixin.qq.com/` → 左侧「草稿箱」/「新的创作」→「图文消息」 |
| 标题 | 上限 64 字；**脚本按 16–24 字产出**，列表页约 13–15 字后截断，核心信息必须前置 |
| 摘要 | ≤ 120 字。不填则自动抓正文前 54 字，**建议手填** |
| 正文 | 无硬上限；深度文 2000–4000 字。段落 ≤ 4 行，段间空行 |
| 封面 | 大图 2.35:1（900×383）；小图 1:1（200×200）。必须在正文外单独上传 |
| 图片 | 正文内图片支持 JPG/PNG，宽度 900px 左右 |
| 外链 | 正文内**仅白名单域名可点**，其余会被剥成纯文本。引流一律用「公众号名片」或引导回复关键词 |
| 发布模式 | 订阅号一天一次群发；「发布」不占群发次数。**默认走草稿箱 + 截图给用户确认后再群发** |
| 特殊 | 原创声明、留言、赞赏需在发布时手动勾选 |

**排版要点**：不用 Markdown 语法，公众号编辑器不识别；用「小标题 + 短段落 + 序号」；重点用加粗，少用颜色。

### 2. 知乎

| 项 | 规格 |
| --- | --- |
| 后台入口 | `https://zhuanlan.zhihu.com/write`（专栏文章）；回答走 `https://www.zhihu.com/question/<id>/answer` |
| 标题 | 建议 20–30 字；**疑问句或结论前置**（「为什么 X」「X 的真相是 Y」）点击率最高 |
| 正文 | 长文友好，2000–6000 字。支持富文本编辑器，识别 `#`/`-`/`1.` 等 Markdown 式输入并即时转换 |
| 图片 | 无严格比例，宽度 ≥ 690px 更清晰 |
| 话题 | 文章最多 3 个；回答可加 5 个。话题决定冷启动流量，**必须填满** |
| 外链 | 未达等级会被折叠；引流用「公众号同名」等文字暗示，不放裸链接 |
| 入口坑 | 编辑器是富文本；用 `agent-browser type` 直接输入纯文本后，Markdown 标记**不会被自动渲染**，需改走「粘贴 HTML」或用编辑器工具栏 |

### 3. 今日头条

| 项 | 规格 |
| --- | --- |
| 后台入口 | `https://mp.toutiao.com/profile_v4/graphic/publish` |
| 标题 | **上限 30 字**，超出直接截断。脚本按 15–25 字产出 |
| 正文 | 建议 1000–3000 字，一段不超过 2 行（移动端阅读） |
| 摘要 | ≤ 100 字 |
| 封面 | 单图 1:1 或三图 3:2；三图模式点击率更高 |
| 分类/标签 | 必选分类；标签 ≤ 3 个 |
| 审核 | 新号有「新手期」，机器审核 + 人工抽检，涉及医疗/金融/时政会延迟或驳回 |

## 二、短图文平台

### 4. 小红书

| 项 | 规格 |
| --- | --- |
| 后台入口 | `https://creator.xiaohongshu.com/publish/publish?source=official` |
| 标题 | **≤ 20 字**，就写满 20 字，不要浪费 |
| 正文 | **≤ 1000 字**，最优 300–600 字。首行必须钩子（痛点或结论），否则折叠后没人点 |
| 图片 | **3:4 竖版 1080×1440 最佳**，1–18 张。首图定生死，需带大字号文案 |
| 话题 | 正文内以 `#话题` 形式书写，5–10 个；末行集中放，前面留 2 个埋进正文 |
| 正文结构 | emoji 分段 + 短句 + 清单式（`1️⃣ 2️⃣ 3️⃣`） |
| 发布坑 | 编辑器是富文本，换行用真实换行而非 `\n` 字面量；话题需从下拉联想框点选才生效，纯文本 `#xxx` 可能不被收录 |
| 风控 | 明显导流（微信/链接/手机号）会限流甚至封号。引流话术走「主页」「评论区」 |

---

### 5. 微博

| 项 | 规格 |
| --- | --- |
| 后台入口 | `https://weibo.com/` 首页发布框；长文走 `https://weibo.com/ttarticle/p/write` |
| 正文 | 普通用户 ≤ 2000 字；**常规帖建议 100–300 字**，超过 140 字折叠「展开」 |
| 图片 | 最多 9 张，1:1 或 4:3 |
| 话题 | `#话题#`（前后都带井号），1–3 个 |
| 传播组合 | 图 + 话题 + `@` 相关账号，三者齐上效果最好 |
| 入口坑 | 首页发布框是 SPA，直接输入文本后需 `blur` 或点「发送」按钮才提交；话题用 `#` 会弹出联想，需回车确认 |

## 三、跨平台改写对照（速查）

| 维度 | 公众号 | 知乎 | 头条 | 小红书 | 微博 |
| --- | --- | --- | --- | --- | --- |
| 标题字数 | 16–24 | 20–30 | 15–25 | ≤20（写满） | 无（正文即标题感） |
| 正文字数 | 2000–4000 | 2000–6000 | 1000–3000 | 300–600 | 100–300 |
| 段落长度 | ≤4 行 | ≤5 行 | ≤2 行 | 1–3 句 | 1–2 句 |
| 语气 | 稳重、有出处 | 论证、有逻辑 | 通俗、快节奏 | 第一人称、口语 | 观点锐利、可带情绪 |
| emoji | 少 | 几乎不用 | 少 | 大量 | 适量 |
| 小标题 | 需要 | 需要 | 少用 | 不需要 | 不需要 |
| 话题/标签 | 无 | 3 个 | ≤3 标签+分类 | 5–10 个 | 1–3 个 |
| 图片 | 2.35:1 封面 | 任意 | 1:1 或 3:2 | 3:4 竖版 | 1:1 |

## 四、发布前的账号前提（先与用户确认，缺失则无法自动发布）

- 公众号：需**已认证或已注册的订阅号/服务号**，且有群发权限；个人号无留言功能。
- 知乎：账号需可写专栏文章（部分新号限制）。
- 头条：需完成实名认证，否则只能存草稿。
- 小红书：建议账号有一定活跃度；新号频繁发布易触发风控。
- 微博：一般无门槛。

**若某平台缺账号或权限，跳过该平台并在台账中标记 `skipped:no_account`，不要伪造成功。**

## 五、数据后台入口与可回收指标

发布后回抓数据的地址与口径。配合 `scripts/stats_log.py` 使用，操作步骤见 `publish-runbook.md` 第六节。

| 平台 | 数据后台入口 | 可回收指标 | 抓取注意 |
| --- | --- | --- | --- |
| 公众号 | `mp.weixin.qq.com` →「数据」→「内容分析」 | 阅读、分享、在看、点赞、留言数 | 数据 T+1 才稳定；当日抓到的数会偏低 |
| 知乎 | `www.zhihu.com/creator` →「内容分析」 | 阅读、赞同、评论、收藏 | 专栏文章与回答分开统计，别混 |
| 头条 | `mp.toutiao.com` →「数据」→「内容分析」 | 推荐量、阅读、点击率、涨粉 | **推荐量 ≠ 阅读量**，两个都要记 |
| 小红书 | `creator.xiaohongshu.com` →「数据中心」→「笔记分析」 | 曝光、点击、点赞、收藏、评论、涨粉 | 面板为 canvas 图表，`snapshot` 可能抓不到数值，需截图人工读 |
| 微博 | 个人主页该条微博下方，或 `data.weibo.com` | 阅读、转发、评论、点赞 | 单条阅读数仅自己可见，必须已登录 |

**口径不可硬对齐**：头条的「推荐量」大致对应小红书的「曝光」，而公众号根本没有曝光概念。跨平台对比只比两者都有的**阅读**与**点赞**，其余指标只在同平台内做纵向对比。

**推荐抓取时点**：发布后 24h、72h 各一次，尽量同一时段，详见 `publish-runbook.md`。
