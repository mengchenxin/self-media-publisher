# 一稿多改规则

从一篇「母稿」派生各平台版本的改写方法论。目标不是「删减」，而是**用同一批事实为不同受众重写**。

---

## 〇、产出文件的格式约定（预检脚本依赖，先看这个）

每个平台版本写成独立文件，**文件名固定、不能改** —— `scripts/preflight_check.py` 靠文件名识别平台并套用对应规格：

| 文件名 | 平台 |
| --- | --- |
| `wechat.md` | 公众号 |
| `zhihu.md` | 知乎 |
| `toutiao.md` | 头条 |
| `xiaohongshu.md` | 小红书 |
| `weibo.md` | 微博 |

文件结构 = frontmatter + 正文：

```markdown
---
platform: xiaohongshu
title: 居家办公3年｜我以为很爽，结果效率崩了
tags: 居家办公, 远程办公, 效率, 职场, 自我管理
images: images/xhs-1.jpg, images/xhs-2.jpg
---

<正文>
```

- `title` —— 发布时填进标题框的字符串。**必填**，不要依赖正文首行充当标题。
- `tags` —— 逗号分隔，数量填到该平台上限（规格见 `platform-specs.md`）。
- `images` —— 该平台要用的图片，路径相对文章目录，**第一张是封面/首图**。

缺 frontmatter 时预检会退化推导（标题取正文首行、话题数内联 `#标签#` 计数），但会告警，而且容易误判（例如把微博正文第一行当成标题）。所以**每个平台版本都老老实实写 frontmatter**。

---

## 一、为什么不能复制粘贴

- **头条**会做全网重复度检测，跟公众号正文雷同会压推荐量。
- **知乎**判定「回答/文章重复」会降低权重，且站内重复内容被折叠。
- **小红书**对搬运内容有独立风控。
- 结果：同一内容直接贴 5 个平台，最坏情况是**每个平台都不给流量**。

因此每个平台版本必须有**实质差异**，至少要动三处：标题、开头段、段落顺序或案例。

---

## 二、先写母稿（Stage 2 产出）

母稿是**唯一的事实容器**，长度取最长平台（3000–4000 字），写的时候按「信息块」组织，方便后续拆装。

母稿结构（每块独立成节，用标记分隔）：

```
[HOOK]   开篇钩子：一个具体场景 / 一个反常识结论 / 一个数字
[THESIS] 核心主张：一句话说清本文到底要证明什么
[ARG-1]  论点 + 证据（数据、来源、时间）
[ARG-2]  论点 + 证据
[ARG-3]  论点 + 证据
[CASE]   1–2 个具体案例或亲身经历
[GOLD]   3–5 句可独立成立的「金句」
[ACTION] 行动建议 / 结论
[LIMIT]  边界与例外（避免绝对化，也提升可信度）
```

**母稿里的每个数字都必须带来源和年份**。没有来源的数字，标注 `未核实`，改写时不许出现在任何平台版本里。

---

## 三、各平台重组规则

按 `references/platform-specs.md` 的字数与语气规格，从信息块里挑装：

| 平台 | 取哪些块 | 关键动作 |
| --- | --- | --- |
| 公众号 | 全部 | 加小标题；`[LIMIT]` 放结尾提升可信度；开头 3 行内必须出现 `[HOOK]` |
| 知乎 | `[THESIS]`+3 个 `[ARG]`+`[CASE]` | **论点顺序改成递进或反驳式**；保留来源与数据（知乎受众吃这个）；弱化营销 |
| 头条 | `[HOOK]`+2 个 `[ARG]`+`[CASE]` | 段落砍到 ≤2 行；术语替换成大白话；案例前置 |
| 小红书 | `[HOOK]`+`[CASE]`+`[ACTION]` | 改第一人称；emoji 分段；结尾抛互动问题；`[GOLD]` 拆成小标题 |
| 微博 | `[GOLD]`+`[THESIS]` | 只留一个最锐利的观点；带情绪；结尾可引导评论 |

**改写红线**：
- 不新增母稿里没有的事实。
- 不改数字、不改来源年份。
- 不把「多数情况下」改成「一定」——这是合规风险（见第四节的绝对化用语）。

---

## 四、标题生成法

每个平台出 **3 个候选**，让用户挑，最后记录选中的那个。

5 种句式，按平台偏好选：

1. **数字清单**：`3 个方法，让 X 从 A 变成 B` → 头条、小红书
2. **反常识**：`X 不是 Y，而是 Z` → 知乎、微博
3. **痛点提问**：`为什么你做了 X，却依然 Y？` → 知乎、小红书
4. **身份代入**：`做 X 的人，都在偷偷用这一招` → 小红书、公众号
5. **结论前置**：`X 的真相：Y` → 公众号、头条

标题自检：
- 字数是否在该平台上限内？（公众号 64 / 头条 30 / 小红书 20）
- 移动端截断后，前 13–15 字能否独立成句？
- 是否含绝对化用语（`最`、`第一`、`唯一`、`顶级`、`100%`）？——**有就必须改**。

---

## 五、开头钩子模板（前 3 行决定跳出率）

- **场景钩**：`上周三，我在 X 上看到一条消息，说……`
- **数字钩**：`一组数据：A 是 B 的 3 倍。这不是巧合。`
- **反常识钩**：`关于 X，多数人的理解是反的。`
- **代价钩**：`因为没做 X，我损失了 ……`

小红书必须用「场景钩」或「代价钩」；知乎必须用「反常识钩」或「数字钩」。

---

## 六、改写完成检查清单

每个平台版本产出后逐条核对：

- [ ] 字数在该平台区间内（不是「不超过」，是「落在区间」）
- [ ] 标题字数合规、无绝对化用语、前 13 字可独立成句
- [ ] 开头 3 行内出现钩子，且钩子类型符合该平台偏好
- [ ] 段落长度符合该平台规格
- [ ] 话题/标签数量填到该平台上限
- [ ] 与母稿及其他平台版相比，标题 + 开头 + 段落顺序至少 3 处不同
- [ ] 所有数字带来源年份，无 `未核实` 内容
- [ ] 已带 frontmatter（`title` / `tags` / `images`），文件名与平台一一对应
- [ ] 已过 `scripts/preflight_check.py`，`verdict` 不为 BLOCK

## 七、示例：同一母稿的 5 个标题

母稿主题：*远程办公三年后，我的效率其实下降了*

| 平台 | 标题 |
| --- | --- |
| 公众号 | 远程办公第三年，我发现效率在悄悄下降 |
| 知乎 | 为什么远程办公久了，效率反而变低？ |
| 头条 | 在家上班 3 年，我的效率越来越低 |
| 小红书 | 😭居家办公3年｜我以为很爽，结果效率崩了 |
| 微博 | 远程办公的问题不是自律，是没有「下班」这个动作。 |

注意差异：受众不同 → 语气不同 → 句子结构不同，但**核心事实完全一致**。
