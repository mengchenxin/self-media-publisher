# 母稿模板

复制本模板开始写作。**顺序不要改** —— 每个块都有下游用途，改写阶段按块拆装。

产出路径约定：

```
<输出目录>/<文章slug>/
├── master.md          # 本模板产出的母稿（唯一事实来源）
├── wechat.md          # 公众号版  ┐
├── zhihu.md           # 知乎版    │ 这五个文件名固定，不可改 ——
├── toutiao.md         # 头条版    │ preflight_check.py 靠文件名识别平台
├── xiaohongshu.md     # 小红书版  │
├── weibo.md           # 微博版    ┘
├── images/            # 配图与封面（含 render_card.py 产出的卡片 html + png）
├── publish-log.csv    # 发布台账（状态 + 链接）
└── stats-log.csv      # 数据台账（24h / 72h 指标）
```

各平台版本必须带 frontmatter（`title` / `tags` / `images`），格式约定见
`references/rewrite-playbook.md` 第〇节。缺了预检会告警且容易误判。

---

```markdown
# [母稿] <文章工作标题>

- 文章slug: <英文短名，用于目录命名>
- 目标平台: 公众号 / 知乎 / 头条 / 小红书 / 微博
- 核心受众: <一句话描述，例如「30 岁上下的互联网从业者」>
- 写作日期: YYYY-MM-DD

## [HOOK] 开篇钩子

<一段场景 / 一个反常识结论 / 一组数字。控制在 3 行内。>

## [THESIS] 核心主张

<一句话说清全文要证明什么。>

## [ARG-1] 论点一

<论点陈述>

- 证据: <数据>
- 来源: <机构 + 年份 + 链接或报告名>
- 判断: <这条证据支持到什么程度，不要过度推论>

## [ARG-2] 论点二

同上结构。

## [ARG-3] 论点三

同上结构。

## [CASE] 案例

<1–2 个具体案例。亲身经历优先，其次公开可查的事件。>

## [GOLD] 金句

1. <可独立成立的句子>
2. <可独立成立的句子>
3. <可独立成立的句子>

## [ACTION] 行动建议

<读者读完能立刻做什么。要具体到动作。>

## [LIMIT] 边界与例外

<本文结论不适用的情况。这一段既提升可信度，也规避绝对化风险。>

---

## 事实核对清单（写完必过）

- [ ] 每个数字都带来源与年份，无 `未核实` 残留
- [ ] 每个论断区分了「事实」与「我的判断」
- [ ] `[LIMIT]` 已填写，未出现「一定」「必然」类无边界表述
- [ ] 全文无广告法绝对化用语（可跑 `scripts/preflight_check.py` 验证）
- [ ] 核心受众读第一段就知道「这跟我有关」
```

---

## 使用要点

1. **先填事实，后写文字。** 块里只放要点，不要一开始就打磨句子 —— 打磨留给各平台版本。
2. **`未核实` 是硬标记。** 任何没有来源的数字先标 `未核实`，改写阶段会被检查清单拦下。
3. **金句单独抽出来。** 微博版基本只靠 `[GOLD]` 和 `[THESIS]` 存活，写母稿时就抽好能省大量时间。
4. **`[LIMIT]` 不是客套。** 它同时承担合规职责 —— 有了边界，前文的强表述才站得住。
